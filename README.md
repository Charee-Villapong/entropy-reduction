# entropy-reduction

エントロピー削減の仕組み（複雑さの計測と定期的削減）の実装リポジトリ。

## 目的

「測る → 候補を出す → 判定する → 本人が仕分ける → 削減を実行する → 測り直す」の一巡をコードで担保し、週次の定期タスク「エントロピー削減タスク」として回す。
月次棚卸し（inventory-harness）が検出と深い点検を担い、本仕組みは実行の一本窓口を担う。

## 設計の要点

- **疎結合**：計測・候補検出・判定・仕分け提示・実行・保存率テスト・再計測は、それぞれ独立した tool 単位とし、単体でテスト・差し替え・再実行できる形にする。受け渡しはファイル（JSON）の入出力形式で境界を検査できる形にする。
- **指標**：行数・削減率は目標にしない。意味の保存率（確認問題の固定セットで測る）を絶対の制約とし、到達可能性100%を保つ。削減量は結果として記録するだけ。
- **実行ガード**：削減の実行対象は、専用タブ「エントロピー候補」で本人が仕分けた行のみにコードで限定する。
- **計測の共通化**：計測は inventory-harness の既存部品（対象の列挙・集計）と、そのランの状態ファイルを候補入力として再利用し、同じ対象を数え直さない。
- **候補の提示は専用タブに一本化**する。提示先はタスク台帳と同じスプレッドシート内の専用タブ「エントロピー候補」で、本人の仕分けは同タブの「仕分け」列（プルダウン）で一度だけ行う。
- 費用は0円（ローカル実行のみ、外部送信なし）。
- 文章ルールのコード化（AIエージェント改善タスクフォース）もエントロピー削減の一形態として扱う（詳細は `docs/SPEC.md` §9）。

## 構成

- `docs/SPEC.md` — 完了の定義とユニット契約
- `src/entropy_reduction/` — 各 tool 単位の実装
- `tests/` — 仕様のみから先行作成した受け入れテスト

## 運用

- 週次 cron `entropy-reduction-weekly`（金曜 10:08）が一巡（計測→候補→判定→提示）を回す。仕分け後の実行は、シート監視 hook `entropy-sort-sheet-watch` の検知時にも起動する（詳細は `docs/SPEC.md` §8）。
- 埋め込みモデルは `cl-nagoya/ruri-v3-310m`（設定 `embedding_model` で差し替え可能）。
- 仕分けの読み取りはユニット `decisions` が担う（「仕分け」列の `削除`／`統合`／`符号化`／`保持` を execute の入力へ変換。対応表は設定 `decision_labels` で差し替え可能）。
